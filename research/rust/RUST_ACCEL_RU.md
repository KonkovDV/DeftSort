# Ускорение CPU-кода на Rust (ветка rust-accel, всё только локально)

Замеры: Python 3.10 и numpy 1.21.5/1.26.4, как в образе Humble; реальная модель руки, 36 сфер робота и 1403 сферы сцены; кадры Kaggle v7.

## Профиль до ускорения (cProfile, 4 объекта, 60 с)
| Место | Доля |
|---|---|
| CollisionModel.valid через certify (проверка пути) | ≈64% |
| Chain.ik: fk/rotation/jacobian/SVD | ≈35% |
| perception: table_plane 0.16 с/кадр, segment 0.12 с/кадр, trays.locate 0.015 с/вызов | — |

## Сквозные замеры
- Полный цикл: 6 кадров восприятия и 10 объектов планирования (candidates → plan_pick → plan_place_yaw). Было 103 с, стало около 1.2 с: планирование 0.6 с, восприятие 0.6 с. Результаты бит-в-бит совпадают с master.
- Планирование одного объекта: было около 10 с, стало около 0.06 с, это примерно 170×.
- Скрипт досягаемости diag/reach3.py, 12 раскладок: было 161 с, стало 1.1 с, это примерно 147×. Исходы совпадают.
- Тесты: прогон 61 старого теста раньше занимал 36 с, сейчас весь набор проходит за 4 с без тестов эквивалентности.

## Решения по модулям: переносить на Rust или оставить
| Модуль | Решение | Причина и измеренный выигрыш |
|---|---|---|
| kinematics.Chain fk/frames/jacobian/ik | **Rust** | Узкое место; 8–87× через Python |
| planning.CollisionModel valid/certify/certify_box | **Rust** | Главное узкое место; 109× и 90–150×. Точная сеточная broad-phase и порядок проверки coarse-to-fine |
| perception.table_plane | **Rust** (только подсчёт инлайеров) | 8×. ГСЧ и уточнение через SVD остаются в NumPy, чтобы план совпадал бит-в-бит |
| perception.segment | **Rust** (заливка) | 10×. Признаки (медиана, квантиль) считаются в NumPy, их доля мала |
| trays.locate | NumPy-оптимизация | Хроматичность считается только по окну. 1.7×, результат идентичен на 558 случаях. Переносить на Rust незачем |
| arm.table_env / tray_env | NumPy и мемоизация | Сферы неизменяемы, сцена повторяется. Около 0.4 с на 10 объектов уходит |
| grasp.candidates/footprint | Оставить | 3–4 мс на объект, меньше 1% цикла |
| node.identify (Hungarian, scipy) | Оставить | Меньше 1 мс |
| node (rclpy-обвязка), grip, budget, sensing | Оставить | Обвязка ROS и логика; на CPU выигрыша нет |
| geometry (pose, quaternion) | Оставить | Вызывается редко; горячий rotation заменён предвычисленными K и K² (тот же результат) |
| tools/fit_spheres.py | Оставить | Офлайн, запускается один раз, 3.5 с. Порт сэкономит около 3 с один раз |
| fixes/diag reach*.py | Без порта | Используют библиотеку и ускоряются сами в 147× |
| Rayon-параллелизм | Выключен по умолчанию | На коробке (≈1.7 эффективных ядра) certify с rayon медленнее: 3.8 мс против 3.0 мс. На машине проверки CPU делится с Isaac Sim. Включается через TEAM048_ACCEL_PARALLEL=1 |
| panic=abort | Нет, unwind | PyO3 превращает panic в исключение, после чего обвязка переходит на NumPy. С abort любая паника убила бы узел посреди задания. Разница в скорости несущественна |

## Эквивалентность (test_accel_equivalence.py и proptest)
- FK, frames, якобиан: 6000 случайных конфигураций, разница 0.0, то есть бит-в-бит.
- ИК с нуль-пространством и без него: 2000 случайных целей, 2000 из 2000 совпадают, максимальная разница 2.7e-12, расхождений 0.
- valid: 6000 конфигураций с инфляцией и без, вердикты идентичны во всех трёх реализациях (reference, NumPy-vec, Rust).
- certify и certify_box: 120 путей, идентичны. Изменения margin и сцены доходят до Rust.
- table_plane и segment: 12 кадров v7, плоскость, пиксели и признаки идентичны.
- Исключения сохранены: ValueError на выходе за пределы, на неверных параметрах ИК и на det-проверке поворота.
- Отказ расширения проверен: при ошибке ядра включается NumPy, и результат тот же.
- Rust proptest, 10 свойств: ортонормальность FK, якобиан против конечных разностей, обратимость log/exp, сходимость ИК, реконструкция SVD, точность broad-phase против перебора, совпадение порядка certify и параллельного варианта, перестановка coarse-to-fine, разбиение заливкой, подсчёт инлайеров против скалярного.

## Развёртывание
- vendor/team048_accel-0.1.0-cp310-abi3-manylinux2014_x86_64.whl, 340 КБ: собран через zig, нужен glibc не новее 2.14, AVX-инструкций нет (базовый x86-64, без target-cpu=native). Проверен на Python 3.10 с numpy 1.26.4 (numpy<2 в образе) и 1.21.5, а также на Python 3.13 с numpy 2.5.
- setup.sh: ставит wheel по SHA256, при неудаче собирает из исходников (rustup, при необходимости gcc, maturin). Всегда завершается с exit 0, а без модуля работает NumPy-эталон. Оба пути проверены в чистом venv.
- COLCON_IGNORE лежит в rust/ и vendor/, так что colcon build не затронут.
- Профиль release: opt-level=3, lto="fat", codegen-units=1, strip.

## Что перенесено в фазе 2
| Функция | Как | Точность |
|---|---|---|
| ГСЧ RANSAC | PCG64 + `choice(n,3,replace=False)` NumPy (Floyd + `_shuffle_int`), состояние из `np.random.PCG64(seed).state` | бит-в-бит (72 случая в тестах, 520 при разработке) |
| table_plane | кандидаты + отсечённый подсчёт «первый максимум» (останов, когда partial+остаток ≤ best), SoA, AVX2 с выбором в рантайме | бит-в-бит; SVD-уточнение оставлено в LAPACK |
| deproject | одно ядро, фиксированный порядок | 0.0 на 31 кадре |
| table_region, tray_mask | маски окна/прямоугольников (в т. ч. повёрнутых) | поэлементно идентичны |
| trays.detect | выбор пикселей (окно + полоса высоты + хроматичность) одним проходом; h = P@n+d остаётся NumPy; развёртка min_area_rect по 91 направлению (квантили 'linear' через select_nth); извлекается только крупнейшая компонента | бит-в-бит на numpy<2 (279 вызовов) |
| segment | маска + заливка + статистики компонент (медианы, квантиль высоты, цвет) | пиксели/центроид/рамка/цвет — точно; квантиль высоты ≤ 1e-12 (BLAS gemv NumPy с FMA) |
| grasp.footprint / клиренс | caliper-развёртка, min расстояние кончиков | бит-в-бит на numpy<2 |
| Arm.solve | все seed'ы одним вызовом: ik + проверки + valid без GIL | идентично solve_py (300 целей) |
| set_scene | кэш сцены (таблица/лотки/тело как массивы + FastEnv-сетка, ключ по содержимому, с table_x) | repr и массивы идентичны setter'у |
| certify | точный сертификат пропуска: шаг сферы ≤ levers·|Δq|/steps; для пар своих сфер — уточнённая граница; предпросмотр 0.06 м | вердикты = проверке всех сэмплов (800 путей Rust, 40 NumPy); граница levers проверена на реальной модели |
| solve_batch (rayon) | для офлайн-карт досягаемости | — |

## Что осталось в Python и почему
| Место | Причина |
|---|---|
| SVD уточнения плоскости, eigh в identify | LAPACK; замена 3×3 сэкономила бы ≈4 мс/кадр, но сдвинет результат на ~1e-15 и решения перестанут совпадать бит-в-бит |
| h = P@n+d в trays.detect и plane_inliers | BLAS-путь NumPy зависит от CPU (FMA); пересчёт в Rust дал бы ≤1 ulp на границе полосы → другие решения |
| scipy.ndimage.label, ConvexHull (qhull), linear_sum_assignment | уже C; 0.6 мс/вызов и меньше |
| near_edge (5 мс, только в survey), identify (5 мс) | вне цикла захвата или <10% кадра и упираются в LAPACK |
| node.py (rclpy, логи, конечный автомат), grip, budget | обвязка ROS; решения и логи должны остаться теми же |
| Пул процессов study-скриптов | уже параллелен (procs=7); rayon внутри дал бы переподписку, поэтому TEAM048_ACCEL_PARALLEL по умолчанию выключен |

## Тесты
- test_accel_phase2.py (14 тестов) + test_accel_equivalence.py; остальные тесты compliance.
- С Rust: 110/110 (numpy 1.21.5 и 1.26.4, Python 3.10); без Rust (TEAM048_ACCEL=0): 88 + 22 skip (тесты эквивалентности).
- numpy 2.5.1 / Python 3.13: 110/110; там NumPy сам считает xy@u с FMA, разница ≤4.4e-16, все дискретные решения совпадают — тесты сравнивают float с допуском 1e-12 только при numpy ≥ 2.
- cargo test 18 (proptest), clippy -D warnings (с feature python и без), rustfmt --check.

## Развёртывание
- vendor/team048_accel-0.2.0-cp310-abi3-manylinux2014_x86_64.manylinux_2_17_x86_64.whl, glibc ≥ 2.14, базовый x86-64; AVX2-ядро подсчёта выбирается в рантайме (TEAM048_ACCEL_NO_AVX2=1 — принудительно базовый путь).

- Старый модуль (API 1) с новым Python-кодом: функции фазы 2 автоматически идут через NumPy.
