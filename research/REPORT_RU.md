# Сортировка объектов пула 3 гуманоидом TienKung 2.0 Pro: восприятие только по сенсорам, отказ от попытки по порогу и планирование захвата
Команда 048 · Isaac Sim 5.0 / Isaac Lab 2.2 / ROS 2 Humble · отчёт от 08.11.2026 (MSK)

## Аннотация
Конвейер устроен так. По RGB-D камеры робота находится плоскость стола (RANSAC), затем стол сегментируется на объекты. Каждый объект описывается компактными признаками: размеры, высота, цвет, гистограмма RGB. Классификатор — случайный лес с дополнительным классом MERGED (два слипшихся объекта). Если уверенность ниже порога, робот отказывается от попытки. Захват планируется по геометрии видимого облака точек; априорные данные взяты из USD объектов и используются только офлайн.

Оценка сделана на 520 синтетических кадрах (Kaggle T4). Кросс-валидация — GroupKFold по раскладкам. При пороге 0.8 доля принятых одиночных объектов в пуле 3 составила 0.920 [0.899; 0.938], ошибок 0 из 1738 (верхняя 95% граница риска 0.0021). Проверка на реальном роботе в симуляторе пока заблокирована: USD робота лежит в GitHub-релизе, а GH_TOKEN не выдан.

## 2. Методы
### 2.1 Восприятие (только сенсоры)
1. Карта глубины переводится в облако точек.
2. Плоскость стола находится RANSAC'ом.
3. Точки над плоскостью кластеризуются.
4. Для каждого кластера считаются признаки f6 (отсортированные габариты основания, 98-й перцентиль высоты, медианный RGB), гистограмма RGB 4×4×4 и log(npix).
5. Случайный лес (300 деревьев) обучен с классом MERGED (вес 3).

Данные о положении объектов из USD или физического движка во время работы не используются.

### 2.2 Модель решения
Обозначения:
- q — вероятность верной классификации;
- g — вероятность успешного подъёма (провал подъёма не штрафуется);
- d — вероятность уронить объект или положить его не в ту зону после подъёма.

Ожидаемый выигрыш попытки: E = 10·g·[(1−d)(2q−1) − d].

Пытаться стоит при q > 1/(2(1−d)). Множитель g на знак не влияет, поэтому пороги от него не зависят. При лимите 45 с на объект и тай-брейке по времени объекты упорядочиваются по E/t̂: сначала изолированные коробки, затем банки, затем посуда. Если оставшееся время меньше t̂ для данного объекта, робот от него отказывается.

### 2.3 Захват
Габариты берутся по минимальному и максимальному калиперу выпуклой оболочки видимого основания.
- **Коробка и банка:** боковой захват поперёк минимальной оси.
- **Банка, дополнительно:** окружность подгоняется МНК к срезу на средней высоте, это исправляет недооценку диаметра по видимой половине цилиндра. Подгонка принимается только при невязке меньше 4 мм.
- **Посуда:** щипковый захват за край сверху.

Кандидат отбрасывается, если w + 2·margin > W_MAX или если коридор пальцев пересекается с другими сегментами.

W_MAX = 0.09 м — это параметр. Реальное раскрытие кисти Inspire станет известно только после получения ассетов.

Скрипты: `grasp/grasp.py`, `grasp/eval_grasp.py`, `grasp/object_priors.py`.

## 7. Обновление 08.11.2026 (вечер): реальная кинематика, кисть, интеграция
### 7.1 Источник данных
Получены официальные ассеты (`gh` под учёткой пользователя, только чтение; `get_assets.sh`; релиз репозитория nssr-uwt-polygon, коммит 08247fc): USD робота, склад, URDF `tiangong_pro_with_hands.urdf` (62 подвижных сустава). Загружены в ПРИВАТНЫЙ датасет Kaggle `dmitrijkv/team048-polygon-assets`.

### 7.2 ИК и самоколлизии (`ik/arm.py`, в решении `team048_solution/arm.py`)
- Цепь pelvis→{left,right}_tcp_link из URDF (7 DoF; `body_yaw` зафиксирован как калиброванный сустав), пределы суставов из URDF, скорость min(URDF, 0.8 рад/с).
- ИК: ограниченный DLS с SVD-демпфированием и бэктрекингом (Buss 2004; Nakamura & Hanafusa 1986), несколько затравок.
- Самоколлизии: мешей STL в URDF нет, поэтому оболочка рук — цепочки сфер, радиус из тензора инерции (эквивалентный цилиндр, ×1.25, 2.5–9 см); туловище, голова, вторая рука, бёдра и стол — сферы в системе pelvis; проверка всего заметаемого пути с консервативной добавкой (рычаг × шаг), как в v4 `certify`. Это важно, т.к. по уточнению 3 ноября самоколлизии в симе выключены, но проверяются судьями вручную.
- Траектория: синхронизированное движение суставов (каждый сустав приходит одновременно; прямая в пространстве суставов, совпадающая с сертифицированным отрезком), пик ≤0.8 рад/с; замыкание по `/joint_states` с компенсацией недолёта ПД до 2 итераций.
- Тесты `ik/test_arm.py`: 7/7 OK (пределы из URDF, FK↔IK, детекция самопересечения, раскрытие кисти, отображение осей захвата, лимит скорости, отказ при слишком широком объекте).
- Достижимость (сетка зоны спавна x 0.26–0.50, y ±0.52, захват сбоку): правая рука покрывает y ≤ 0.04…0.12, левая y ≥ −0.12 после учёта симметрии оси смыкания; вместе — вся зона. Время планирования ≈1.9 с на объект (CPU).

### 7.3 Раскрытие кисти Inspire (оценка по URDF)
Кончики пальцев оценены как начало дистальной фаланги + 2×смещение её центра масс (мешей нет). При большом пальце в оппозиции (`thumb_1` = 1.246 рад) расстояние большой–(указательный+средний)/2 ≈ **10.5 см** (обе кисти). Рабочий предел W_MAX = 10.5 − 1 см = 9.5 см. Следствие для банок: широкая банка Saccharomyces (7.4 см) теперь проходит; горчица (9.7×6.7) — только по узкой оси 6.7 см.

### 7.4 Идентификация объектов по списку задачи
`/sim/task` публикует перечень объектов раскладки и их категории (разрешённый канал задачи, не позы). Классификация сведена к назначению «сегмент ↔ объект из списка» (венгерский алгоритм) по геометрическим априори (высота, мин/макс калипер из USD — только офлайн). На 60 кадрах hard-набора: принято 342 из 540 объектов (63 % за один кадр; после каждого снятия объекта кадр переснимается), **ошибок категории 0/342**. Это устойчивее к сдвигу домена, чем RF по цвету (риск 0.08 при сдвиге, §3.1), т.к. опирается на метрическую геометрию глубины.

В `grasp.py` направление подхода было инвертировано (пальцы «от объекта к роботу»). После исправления доля спланированных захватов на тестовых кадрах выросла с 18/32 до 27/32.

## 9. Дополнение 09.11.2026: проверенные первоисточники для лёгкого RGB-D манипулирования
(Ниже только опубликованные работы с датами. Утверждений о «результатах ноября 2026» не делается.)
- **Ограниченная ИК.** Beeson & Ames, *TRAC-IK*, IEEE-RAS Humanoids 2015, DOI 10.1109/HUMANOIDS.2015.7363472. Параллельно запускаются Newton/KDL со случайными рестартами и SQP; доля решённых задач на гуманоидных цепях выше, чем у KDL; поддерживаются допуски по каждой декартовой оси. **Вывод для нас:** добавить в DLS-ИК рестарты при упоре в пределы суставов и допуски по рысканью кисти. Это дешёвая мера против ложных «недостижимо».
- **Отказ от решения с гарантиями.** Angelopoulos & Bates, *A Gentle Introduction to Conformal Prediction and Distribution-Free UQ*, arXiv:2107.07511 (2021, v6 2022), включая conformal risk control и модели с отказом. **Вывод:** порог 0.8 можно заменить порогом, откалиброванным на отложенных раскладках с конечновыборочной гарантией доли ошибок среди принятых (≤ α). Калибровать надо на кадрах настоящего сима, а не только своего рендера.
- **Проверка удержания.** Romeo & Zollo, *Methods and Sensors for Slip Detection in Robotics: A Survey*, IEEE Access 8, 2020, DOI 10.1109/ACCESS.2020.2987849. Слип и удержание оцениваются по отношению тангенциальной и нормальной силы и по вибрациям. **Вывод:** у нас есть `effort` пальцев Inspire и 6-осевая сила в запястье (I «Датчики силы»), так что проверку «держу/не держу» после подъёма на 3–5 см делать по ним плюс повторный кадр. Если объект не держится, класть его на стол: по S «Уточнения 2 нояб.» это 0, а не −10.
- Уже процитированные выше (Guo 2017; Geifman & El-Yaniv 2017; Chow 1970; TOPP-RA 2018; Contact-GraspNet 2021; AnyGrasp 2023; cuRobo 2023; SAM 2 2025) остаются в силе.
План приёмки по каждому требованию: `ACCEPTANCE_PLAN_RU.md`.
